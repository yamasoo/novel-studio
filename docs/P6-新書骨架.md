# P6 Step 3：新故事骨架（`studio/spinoff.py`、`tools/spinoff.py`）

> 用參考書的**風格指紋**與**結構 DNA** 產生新書的骨架：一句話前提、賣點、主角、世界觀要點、卷綱。
> 這是 P6 唯一會呼叫模型的一步（約 3 次呼叫）。

## 刻意只送「骨架」

送進提示詞的東西只有：

| 送什麼 | 為什麼 |
|---|---|
| 文字指標（對白比例、句長、段落…） | 讓新書的語感有依據 |
| 章長、章數、視角 | 讓章節結構合理 |
| 3 句代表句（人名已遮） | 給語感範例，但不會帶出角色 |

**不送**：來源正文、設定、追蹤、章綱、事件——所以情節不可能從提示詞漏過去。

## 硬約束與護欄

提示詞裡直接列出**禁用名單**（來源書的角色、勢力、世界觀條目，實測 48 個），並要求
「不得沿用事件順序、名字要原創、不要諧音」。

產出後程式再用 `similarity.names_in()` 驗一次：**撞到就帶著名單重寫一次**。
兩次都撞就把撞到的名字寫進 `護欄` 欄位（CLI 會 exit 1），不會默默放過。

## 用法

```powershell
# 1) 先建一本新書（免費）
python tools/spawn.py --from <書庫>\B 書 --to <書庫>\新書\雪線 --title 雪線

# 2) 產生骨架，存到新書的 候選/新書草稿/
python tools/spinoff.py --from <書庫>\B 書 --to <書庫>\新書\雪線 --provider deepseek \
  --note "想寫極地題材，冷一點"
```

不給 `--to` 就只印出來（不寫任何檔案）。

## 產出長什麼樣

```
# 新書骨架草稿
> 由 P6「A 書→B 書」產生，來源骨架：B 書。滿意再手動套用到 設定/ 與 大綱/。

## 書名建議
雪線之外
## 一句話前提
一名氣象觀測員在極地站發現冰層下的訊號，想查明來源卻被上級阻止。
## 賣點
- 極地孤絕感 / - 科學推理 / - 人性的取捨
## 主角
- **沈若嵐**（觀測員）：動機 查明訊號；弱點 不信人
## 世界觀要點
- 南極站 / - 冰下聲源 / - 遠端指揮部
## 卷綱
- 第1卷《冰下之聲》30 章：調查訊號（卷末：確認有東西在動）
- 第2卷《回聲》28 章：對抗上級（卷末：公開證據）
## 護欄
- 撞到來源名字：沒有
```

## 工作台裡也能做（P6 Step 6）

書架 → 「＋ 開新書」時先選**開書方式**：

| 方式 | 作用 |
|---|---|
| **開書訪談**（推薦） | 先問兩輪，再寫 `CLAUDE.md`、`設定/故事核心.md`、`設定/文風.md`；可以勾「順便產生故事骨架草稿」，草稿只寫到 `候選/新書草稿/`，不會自動套用 |
| **用參考書骨架直接開書** | 需要選一本參考書；產生骨架後直接寫 `CLAUDE.md`、`設定/故事核心.md`、`設定/世界觀/世界觀.md`（有世界觀要點時）、`大綱/全書大綱.md`、`大綱/卷綱_第N卷.md`，跳過開書訪談 |

- 參考書的 seed **不呼叫模型**（`spawn.seed`），開書時就寫進 `設定/文風.md`、`設定/章節結構/結構.md`、`設定/風格指紋.json`、`設定/結構DNA.json`。
- 骨架約 2 次呼叫、1–2 分鐘；跑的時候會顯示「正在產生故事骨架」與目前階段。
- **直接開書只到卷綱**，章綱要用「卷先行 → 排這一卷的章綱」再排；目標讀者、平台、篇幅、讀者契約等骨架沒提到的欄位會標「待補」。
- 直接開書會先備份空白範本到 `.studio/備份/`；`CLAUDE.md` **最後才寫**，前面失敗時書還不是專案，可以直接重跑。
- 護欄撞名時，視窗會出現「有名字和參考書重複（…），請手動改掉」；直接開書仍會寫入，但會提醒。
- **既有書仍只產生草稿**，不會自動套用；「套用卷綱」還沒做（2026-10-31 決策：先只做新書）。

### 既有書也能用（2026-10-30 補）

大綱頁的按鈕列多一顆 **「參考書骨架」**：選一本參考書＋補充要求，就會用同一支 `/api/books/{id}/spinoff`
產生骨架草稿（寫到這本書的 `候選/新書草稿/`），流程跟新書時勾「順便產生故事骨架」完全一樣。

- 只列出**同一書庫的其他書**；書庫只有一本書時會提示「沒有其他書可以參考」。
- 一樣要 API 執行者（Claude Code 不行）、約 3 次呼叫、草稿不會自動套用。
- 對話框會提醒「只取抽象特徵、請只用自有或公有領域作品」。
- 書架的「＋ 開新書」卡片也多了一行「可參考另一本書」，入口比較好找。

### 到底帶了什麼過去

| 會帶到新書 | 內容 | 什麼時候寫 |
|---|---|---|
| `設定/文風.md` | 文字指標（對白比例、句長、段長…），只在空範本時寫 | 開啟參考書時（本機、不呼叫模型） |
| `設定/章節結構/結構.md` | 章長、視角、對白節奏等抽象結構 | 同上 |
| `設定/風格指紋.json` | 13 項指標＋代表句（人名已遮） | 同上 |
| `設定/結構DNA.json` | 視角、章長分佈、對白比例、章長曲線；不含名字與事件 | 同上 |
| `候選/新書草稿/骨架.md`、`骨架.json` | 書名建議、一句話前提、賣點、主角、世界觀、卷綱 | 訪談模式勾「順便產生草稿」、既有書按「參考書骨架」、或直接開書時（呼叫模型） |
| `設定/故事核心.md`、`設定/世界觀/世界觀.md`、`大綱/全書大綱.md`、`大綱/卷綱_第N卷.md` | 骨架的前提／賣點／主角／世界觀／卷綱 | 只有「用參考書骨架直接開書」時（會先備份） |

**不會帶**：來源書的正文、章綱、事件順序、角色名、地名、專有名詞、追蹤資料。訪談模式與既有書的骨架是另外生成的草稿，不會自動套用；只有新書選「直接用骨架開書」才會寫進正式檔案。

### 按下去之後會看到什麼

- 新書流程：按下「建立並開始訪談」後如果選了參考書，會先出現「建立中…」視窗（量指紋與結構，大書約 20–30 秒）。
- 產生骨架：會出現「正在產生故事骨架」視窗，**每秒更新階段**與經過秒數：
  `排隊中… → 量參考書的文風指紋… → 量結構 DNA… → 產生骨架（第 1 次模型呼叫）… → 產生卷綱（第 2 次模型呼叫）… → 完成`
- 任務在背景執行緒跑，關掉視窗不影響；完成後會彈出草稿預覽（直接開書則是「已用骨架開書」）。
- 直接開書**不會先跳書頁**：建立後直接留在「建立中… → 正在產生故事骨架」的進度視窗，
  套用完成才進書，避免短暫看到「不是小說專案」的「開始開書訪談」按鈕而誤會。
- 草稿預覽關掉後，書頁（還沒完成開書訪談、還沒有 `CLAUDE.md` 時）會有「查看參考書骨架草稿」的入口，
  草稿不會因為關掉視窗就找不到。
- JSON 呼叫一律帶 `stage="structured"`：推理模型的思考也算在 `max_tokens` 裡，關掉思考才不會
  只剩空字串或被截斷的 JSON；解析失敗會自動要求模型重出一次。
