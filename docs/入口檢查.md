# 入口重複檢查（2026-10-30）

> 這份只做檢查與記錄，**沒有改任何流程**。目的：寫使用說明時發現「同一件事有好幾個入口」，
> 先列出來，之後再決定要合併哪幾個。

## 高重複：同一件事、語意不同，容易誤用

### 1. 卷綱有兩條路（2026-10-30 已收斂）

**原本：**

| 入口 | 實際行為 |
|---|---|
| 大綱頁「卷綱」按鈕 | `volume_outline`：直接寫正式卷綱檔，沒有草稿、沒有「採用」這一步 |
| 大綱頁卷況卡「開新卷」 | 先產 `大綱/草稿/卷綱_第N卷.md` → 可編輯 → 按「採用」才變正式，並同步全書大綱 |
| 右側動作面板「卷綱草稿」「卷綱更新草稿」 | 同上，走草稿流 |

問題：舊按鈕寫出的檔案是「正式路徑＋狀態草稿」，但閘門與續寫合約都不看狀態，等於一份沒經過確認的卷綱被當成正式；而且只有舊按鈕能改「已確認」的卷。

**現在：**

- 舊的 `volume_outline` 動作與大綱頁「卷綱」按鈕**已移除**。
- 新卷：卷況「開新卷」→ 草稿 →「採用」。
- 既有卷：卷況該卷的「修訂」→ `大綱/草稿/卷綱修訂_第N卷.md` →「看差異」→「套用修訂」（備份、狀態改已確認、同步全書大綱）。
- 正式卷綱只會由「採用」或「套用修訂」寫入，兩者都會先備份。

**還沒做：** 狀態語意。舊書仍有一批「正式路徑＋狀態草稿」的卷綱（`adopt` 之前產生的），目前閘門與合約還是不看狀態；要收緊前得先做一次狀態轉正（或相容規則：「沒有狀態」視為已確認、「草稿」不算）。

### 2. 設定生成有四種入口（2026-10-30 已收斂）

**原本：**

| 入口 | 產出 |
|---|---|
| 設定集「生成草稿」（`gen_drafts`） | 自由描述要什麼 → 寫 `設定/草稿/` |
| 設定集「從大綱長設定」（`bible_from_outline`，新） | 讀大綱／卷綱／章綱 → 寫 `設定/草稿/` |
| 設定集「整理內容入庫」（`intake`） | 貼對話或筆記 → 已定案進正式、討論中進草稿 |
| 角色「新增／補完角色」、勢力「新增勢力」、世界觀「設計世界觀」 | 一次一個項目，可能直接寫正式或草稿 |

問題：四個入口都能「生設定」，使用者不知道差別；同一份草稿也可能用兩種方式產生。

**現在：**

- 設定集頁只剩一顆 **「生成設定」**，先問「你手上已經有什麼」：

| 選項 | 實際動作 |
|---|---|
| 我已經有大綱或卷綱 | `bible_from_outline`（可填參考方向與網址） |
| 我只有一句話或關鍵字 | `gen_drafts` |
| 我剛討論完，有一段文字 | `intake` |
| 我只缺一個角色／勢力／世界觀 | 再選角色／勢力／世界觀 → `character` 或 `free` |

- 角色、勢力、世界觀分頁的「新增…」按鈕，以及草稿分頁的「生成草稿」都移除；草稿分頁只留「草稿轉正式」。
- 右側動作面板仍列四個動作（給進階用法），標籤已加上用途：`生成設定草稿（自由描述）`、`從大綱長設定`、`整理內容入庫（貼文字）`、`新增／補完角色`。

**還沒做：** 動作面板的四個入口還沒有完全隱藏；如果之後要更單純，可以只留分頁與「生成設定」。

## 中重複：功能相同，只是預填不同

### 3. 排章綱（5 個以上入口）（2026-10-30 已處理）

| 入口 | 差異 |
|---|---|
| 大綱頁「排章綱」 | 不預填 |
| 卷況「排這一卷的章綱」 | 預填這一卷的章節範圍 |
| 章節頁「排章綱」 | 不預填 |
| 總覽「排第 N 章起的章綱」 | 預填下一章起 10 章 |
| 單章頁「補章綱」 | 預填該章 |
| 右側動作面板「排章綱」 | 不預填 |

全部都是同一張 `chapter_cards` 表單。**現在**：大綱頁與章節頁改成「下一章起 10 章」、單章改成「補這一章的章綱」；
動作面板標成「排章綱（自訂範圍）」。每個入口都一定帶範圍，空白送出會被擋（見第 4 點）。

### 4. 寫章節（4 個入口）（2026-10-30 已處理）

總覽「寫第 N 章」、章節頁「寫章節」、單章頁「寫這章」、動作面板「寫章節」——同一個 `write` 表單，差在 `from/to` 預填。

**現在**：章節頁改成「寫第 N 章」（下一章）並帶好範圍；動作面板標成「寫章節（自訂範圍、候選稿）」。
另外補了防護：**空白送出不再預設第 1 章**，前端會提示、後端回 400；以前從沒有預填的入口按下去，
很容易不小心排／寫到第 1 章。

### 5. 整章自動（3 個入口）

總覽、章節頁、單章頁（有候選稿時變成「從核對開始」）。同一條管線，差在起點；可以保留，但按鈕文案要一致。

### 6. 草稿轉正式（2 個入口）

| 入口 | 差異 |
|---|---|
| 設定集「草稿轉正式」表單（`promote_drafts`） | 表單裡勾選要轉的草稿 |
| 草稿列表勾選後的「轉正式」（`ef-promote`） | 在列表上勾選後直接轉 |

同一套轉正式邏輯，一個從表單、一個從列表。建議合併成列表勾選。

## 低重複／合理（不同對象或時機）

| 功能 | 入口 | 為什麼合理 |
|---|---|---|
| 追蹤補齊 | 總覽提醒「補齊」、動作面板 `sync_tracking`、定稿步驟自動 | 手動補救 vs 流程自動 |
| 文風 | 設定集「分析／調整文風」、共用庫量測 | 對象不同（這本書 vs 共用範本） |
| 參考書骨架 | 大綱頁按鈕、開新書時勾選 | 時機不同（既有書 vs 新書） |
| 卷末體檢 | 只有總覽一個入口 | 不算重複 |
| 從正文建立設定 | 只有設定集一個入口 | 不算重複 |
| 匯入舊稿、匯出、插圖、搜尋 | 各自單一入口 | 不算重複 |
