# 卷先行：續寫前先把「卷綱 → 整卷章綱」定下來（進行中）

> 2026-10-29 討論後的交接。第一段（卷綱解析＋越界閘門）已實作，草稿流程與整卷章綱還沒。
> 動手前先看 `docs/HANDOFF.md`。

## 為什麼要做

- 2026-10-29 的真 provider 實測（見 `docs/續寫合約.md`）：來源書的卷綱只到第三卷（第 31～50 章），直接從第 51 章連寫，
  章綱是一章一章臨場接的，10 份章綱的產生時間各自隔 6～7 分鐘。
- 專案自己的 `plugin/skills/novel-outline/references/structure.md` 已經寫了：
  「規劃順序永遠是由大到小：全書 → 卷 → 單元 → 章。**沒有卷綱就排章綱，很容易支線亂長、設定膨脹、章末疲軟。**」
- 同類專案（AI Novel Generator 的 volume → arc → scene → chapter plan、Re3 的 overarching plan、Snowflake method）
  都是先規劃再寫，而且每一層都有人工確認點。

## 已定決策（2026-10-29）

1. **卷長不做全域統計，也不設固定目標。** 長篇／短篇與結構在開書時就決定了，每本書的卷長由該書的
   全書大綱與作者決定；工具只顯示「這一卷規劃幾章／實際幾章」，不強制相等或落在某個帶。
2. **卷綱草稿放獨立資料夾**（例如 `大綱/草稿/卷綱_第N卷.md`），不要用「同一個檔名 + `狀態: 草稿`」。
   理由：續寫合約與漂移工具都是掃 `大綱/`、`大綱/卷綱/` 底下的 `卷綱*.md`，同名草稿會被當成正式卷綱吃進上下文。

## 已完成（2026-10-29）

### 第一段：解析與閘門

- `studio/volume.py`：卷綱的唯一解析入口。只看正式卷綱（`大綱/`、`大綱/卷綱/`），草稿資料夾不算；
  同一章同時被「卷」與「幕」覆蓋時以卷為準；`cover()` 回傳缺卷綱的章、`next_no()` 給下一個卷號。
- 續寫合約不再退回第一卷：找不到就明寫「第 N 章不在任何卷綱的章節範圍內（現有卷綱只到第 X 章）」。
- 漂移工具不再退回最後一卷；要把更新附加回卷綱卻找不到對應卷時，直接報錯，不會寫錯檔。
- 整章自動流程加閘門：書有卷綱時，`from～to` 只要有一章不在正式卷綱範圍內就拒絕開流程
  （回 409，訊息會指出缺哪幾章）；沒有卷綱的舊書不擋。
- 驗證（B 書複本，50 章、3 卷）：51～60、61～63 都被擋；31～40 章可建立流程；
  第 61 章的合約不再出現「第一卷」；demo 書 3～5 章照常可跑。

### 第二段：草稿 → 採用（工作台可用）

- 新動作「卷綱草稿」：選卷號＋章節範圍，模型把卷綱寫到 `大綱/草稿/卷綱_第N卷.md`（狀態「草稿」）；
  草稿模式會擋掉寫正式卷綱或其他檔案（`native_files.run_spec` 的 `draft_only="大綱/草稿/"`）。
- 大綱頁多一張「卷況」卡：列出正式卷綱（卷名、章節範圍、狀態）、草稿，以及「開新卷」與「採用」。
- 採用（`volume.adopt`）＝把草稿搬到 `大綱/卷綱_第N卷.md`、狀態改「已確認」、刪掉草稿；
  正式的檔已存在就不動，避免覆蓋。
- 「排這一卷的章綱」按鈕把卷的章節範圍帶進既有的章綱表單（非自動模式會先給總覽，確認後才寫檔）。
- 驗證（不花錢）：假模型的 native 流程把草稿寫進 `大綱/草稿/`、想寫正式檔被擋；
  `adopt()` 後正式檔出現、草稿消失、閘門從「擋 51～60」變成可開；API 函式與 `node --check` 都過。

### 第三段：章綱先行（2026-10-29）

- 整章自動流程的新閘門：範圍內只要有一章**還沒有章綱**，就拒絕開流程，訊息指出缺哪幾章、
  並叫你用大綱頁的「排這一卷的章綱」。章綱沒排好就開寫，等於又回頭一章一章臨場接。
- 排章綱走既有的非自動模式：先給「一章一行」總覽，作者確認後才寫檔（`native_files` 的確認流程）。
- 影響：只有匯入的舊書（例如有一本 34 章、27 章沒有章綱）與新卷的第一章會被要求先排章綱；
  其餘既有書的章綱都是齊的。沒有卷綱的書不擋（維持舊行為）。
- 驗證：同一本複本，51～60（章綱齊）可開；61～65、81～85（缺章綱）被擋，訊息正確。

## 提案流程

```
開新卷
  → 產生卷綱草稿：卷契約（賣點／目標／對手／卷末兌現／新鉤子）、單元表、每單元 3 行
     寫到 大綱/草稿/卷綱_第N卷.md，狀態: 草稿
  → 作者討論、修改、核可 → 定案寫入 大綱/卷綱_第N卷.md（狀態: 已確認）
  → 排整卷章綱：先給「一章一行」總覽表 → 作者確認 → 批次寫入 大綱/章綱/
  → 章綱齊了才進整章自動流程
      └─ 流程閘門（已做）：任一章不在正式卷綱範圍內、或還沒有章綱 → 拒絕並提示缺什麼
  → 卷末：漂移體檢（P5）＋自動駕駛檢查點 → 產出的「卷綱更新草稿」回饋下一卷
```

第 6 步已經有一半：`2ef5403` 的「卷末體檢」會產出「卷綱更新草稿」，不覆蓋原卷綱、由作者決定要不要附加。
「看過才併入」的模式可以跟「開新卷草稿」共用同一套慣例。

### 第四段：更新草稿也統一（2026-10-29）

- 卷末體檢產生的「卷綱更新草稿」改放 `大綱/草稿/卷綱更新_第a-b章.md`，跟新卷草稿同一個資料夾。
- 兩種草稿靠檔名與用途分開：`卷綱_第N卷.md` 是新卷（可「採用」），`卷綱更新_…` 是體檢草稿（只能「附加」）；
  `volume.drafts()` 不會把更新草稿當成新卷，`volume.plan_drafts()` 專門列更新草稿。
- 大綱頁左側清單與「卷況」卡都看得到更新草稿，可直接開檔編輯；附加仍走卷末體檢頁（會先備份原卷綱）。
- 舊的 `候選/卷綱更新_…` 草稿仍可附加（端點兩種路徑都收）。

### 第五段：合約進規劃＋全書大綱同步（2026-10-30）

- 卷綱草稿與章綱的上下文都加了 `設定/續寫合約.md`（不可變事實、已退場角色、未揭示的秘密、未回收伏筆）；
  卷綱草稿會拿掉「卷末承諾」那一段（新卷還不存在），章綱則完整保留（這時卷末承諾已是本卷）。
- 兩個規劃提示詞都多一句 `contract_rule`：合約與大綱衝突時以合約為準、不能復活退場角色、不能提前說破秘密。
- 合約檔不存在或章數變了，會先自動補一份（純本機計算，跟整章自動流程開跑時做的事一樣）。
- 採用卷綱時同步 `大綱/全書大綱.md`：分卷裡沒有第 N 卷就**追加**一節（卷名、章節範圍、卷契約、卷綱檔），
  只追加、不覆蓋；已經有第 N 卷但章節範圍不同就只警告、不改檔；沒有全書大綱也只警告。
- 帶過去的是**卷契約本文**（本卷賣點／主角本卷目標／本卷對手／卷末兌現／卷末新鉤子），不是只有一個檔名連結；
  舊的段落只有「篇幅＋卷綱」時，卷況卡的「同步大綱」會把缺的項目補上（只補不覆蓋，重按安全）。
- 驗證：拿複本試三種情況——沒有第四卷（追加成功）、已有但範圍不同（只警告、檔案沒變）、
  沒有全書大綱（警告）；合約注入實測 4,184 字、去掉卷末承諾後 3,244 字。
  卷五的實際段落補完後長這樣：篇幅、五條卷契約、卷綱連結，第二次同步不再增加任何一行。


### 第六段：章綱體檢＋卷末草稿回饋下一卷（2026-10-30）

- 新增 studio/upcheck.py：把「提前登場」「久別重逢」的規則抽出來，正文與章綱共用。
- 	ools/card_audit.py：正文還沒寫就能掃章綱（例：--from 51 --to 60），有衝突回傳 1。
- 大綱頁卷況卡每卷多一顆「章綱體檢」，列出哪一章的哪個角色提前登場／久別重逢。

## 將來的驗收方式

- 複製一本書 → 產生下一卷草稿 → 作者確認 → 整卷章綱 → 連寫 10 章 → `contract_audit` 0 處；
  且這 10 章的續寫合約「卷末承諾」必須是**本卷**，不是第一卷第 61 章那種錯誤。
- 越界寫作（章號不在任何已確認卷綱）→ 流程拒絕並說明原因，不是靜默 fallback。
