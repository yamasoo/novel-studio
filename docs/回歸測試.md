# 書的回歸測試（`tools/book_eval.py`）

> 目的：改提示詞、改上下文、升級模型之後，**用數字說「有沒有變差」**，而不是憑感覺。

## 三種任務

跑在 `demo/` 三本示範書的**副本**上（原書不動；每次跑都在暫存資料夾，結束就刪）：

| 任務 | 做什麼 | 看什麼 |
|---|---|---|
| `continue` | 遮住最後一章（正文、章節摘要、候選），用前面的資料寫這一章 | 章綱提到的名字有沒有出現、文風偏差、檢查腳本問題數 |
| `deslop` | 對最後一章跑去 AI 味（原稿不動） | 數字保留率、名字保留率、字數比、問題數、文風偏差 |
| `review` | 對最後一章跑審查，讀工作台實際存下來的審查紀錄 | JSON 是否合法、意見數、**引用是否逐字命中**、嚴重度分佈 |

## 怎麼跑

```powershell
python tools/book_eval.py                                  # 假 provider：只驗管線（不花錢，CI 也在跑）
python tools/book_eval.py --provider deepseek              # 真 provider：驗品質（會花錢）
python tools/book_eval.py --books zh-TW --tasks deslop     # 只跑一本、一個任務
python tools/book_eval.py --provider deepseek --baseline eval/results/2026-10-29-1200-real.json
```

結果寫到 `eval/results/<時間>-<fake|real>.json`。給 `--baseline` 就會逐項比對，
有退步會列出（`指標：舊 → 新`）並回傳 1，可以直接接進 CI 或腳本。

## 指標與方向

以**確定性指標**為主（自己算，沒有模型雜訊）：

| 指標 | 方向 | 說明 |
|---|---|---|
| `style_obvious` / `style_slight` | 越低越好 | 和文風目標相比「明顯／稍有」偏離的指標數；`設定/文風.md` 沒填指標時，改用作者自己全部正文當基準 |
| `issues` / `issues_must` | 越低越好 | 該語言的檢查腳本（`check_text.py`）掃出的問題數，`issues_must` 是「必須修」 |
| `names_kept` | 越高越好 | 原稿（或章綱）出現過的名字，改完還有多少比例留著 |
| `digits_kept` | 越高越好 | 數字（年份、金額、章號）是否原樣保留，去 AI 味最容易在這裡出事 |
| `length_ratio_off` | 越低越好 | 字數變化幅度（0＝一字不差，0.5＝多或少一半） |
| `lang_ok` | 越高越好 | 產出語言對不對（英文書不該出現連續中文句、日文書要有假名） |
| `review_json_ok` / `review_quote_hit` | 越高越好 | 審查 JSON 合法、意見引用的原句真的在正文裡（工作台逐字比對，這條壞了就等於審查無效） |

判退步時有容差（見 `TOLERANCE`）：名字保留率 ±5%、數字 ±2%、文風「稍有」±1 條……
避免每次跑都在跳噪音。無法量測的指標記 `-1`（例如樣本不到 300 字），比對時標「無法量測」，不算退步。

## 假 provider 能驗到什麼

`python tools/book_eval.py` 不呼叫模型，只確認：三個任務都跑得完、提示詞組得出來、
回傳的 JSON 能解析、審查紀錄存得下來。**它的分數沒有品質意義**——假 provider 產生的文字很短，
所以 `style_*` 會是「無法量測」、`names_kept` 多半是 0。CI 用這個模式，成本是 0。
