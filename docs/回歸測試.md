# 書的回歸測試（`tools/book_eval.py`）

> 目的：改提示詞、改上下文、升級模型之後，**用數字說「有沒有變差」**，而不是憑感覺。

## 三種任務

跑在 `demo/` 三本示範書的**副本**上（原書不動；每次跑都在暫存資料夾，結束就刪）：

| 任務 | 做什麼 | 看什麼 |
|---|---|---|
| `continue` | 遮住最後一章（正文、章節摘要、候選），用前面的資料寫這一章 | 章綱提到的名字有沒有出現、文風偏差、檢查腳本問題數 |
| `deslop` | 對最後一章跑去 AI 味（原稿不動） | 數字保留率、名字保留率、字數比、問題數、文風偏差 |
| `review` | 對最後一章跑審查，讀工作台實際存下來的審查紀錄 | JSON 是否合法、意見數、**引用是否逐字命中**、嚴重度分佈 |

## 怎麼跑

```powershell
python tools/book_eval.py                                  # 假 provider：只驗管線（不花錢，CI 也在跑）
python tools/book_eval.py --provider deepseek              # 真 provider：驗品質（會花錢）
python tools/book_eval.py --books zh-TW --tasks deslop     # 只跑一本、一個任務
python tools/book_eval.py --provider deepseek --baseline eval/results/2026-10-29-1200-real.json
```

結果寫到 `eval/results/<時間>-<fake|real>.json`。給 `--baseline` 就會逐項比對，
有退步會列出（`指標：舊 → 新`）並回傳 1，可以直接接進 CI 或腳本。
**模式不同就不比**（基線是 real、這次是 fake）——假 provider 的分數沒有品質意義。

另外每次都會寫一份 `…-texts.json`：模型這次寫出來的文字、章綱、以及檢查腳本的問題清單。
**要追「這 3 個必須修到底是什麼」就看這個檔**——不用重跑、也不會把稿子混進你的書。

## 指標與方向

以**確定性指標**為主（自己算，沒有模型雜訊）：

| 指標 | 方向 | 說明 |
|---|---|---|
| `style_obvious` / `style_slight` | 越低越好 | 和文風目標相比「明顯／稍有」偏離的指標數；`設定/文風.md` 沒填指標時，改用作者自己全部正文當基準 |
| `issues` / `issues_must` | 越低越好 | 該語言的檢查腳本（`check_text.py`）掃出的問題數，`issues_must` 是「必須修」 |
| `names_kept` | 越高越好 | 原稿（或章綱）出現過的名字，改完還有多少比例留著 |
| `digits_kept` | 越高越好 | 數字（年份、金額、章號）是否原樣保留，去 AI 味最容易在這裡出事 |
| `length_ratio_off` | 越低越好 | 字數變化幅度（0＝一字不差，0.5＝多或少一半） |
| `lang_ok` | 越高越好 | 產出語言對不對（英文書不該出現連續中文句、日文書要有假名） |
| `card_coverage` | 越高越好 | 章綱裡「比較罕見的用詞」有多少出現在稿子裡（bigram 比對；到處都有的字不計分） |
| `ref_*` | — | **人類原作**在同一張章綱下的同一個指標（`continue` 會先量原作再遮掉它）。只做對照，不判退步 |
| `card_coverage_vs_human` / `names_kept_vs_human` | 越高越好 | 模型 ÷ 人類原作（1.0＝和作者自己寫的一樣）。**看這個，不要看絕對值** |
| `review_json_ok` / `review_quote_hit` | 越高越好 | 審查 JSON 合法、意見引用的原句真的在正文裡（工作台逐字比對，這條壞了就等於審查無效） |

判退步時有容差（見 `TOLERANCE`）：名字保留率 ±5%、數字 ±2%、文風「稍有」±1 條……
避免每次跑都在跳噪音。無法量測的指標記 `-1`（例如樣本不到 300 字），比對時標「無法量測」，不算退步。

## 長篇 fixture（20 章以上）

示範書只有 2 章，量不到「第 200 章」的行為。把本機的書加進來（**不會動到原書**，每次跑都複製到暫存資料夾）：

```powershell
# 1. 複製範例，改路徑與章號（這個檔不進版控，因為是本機路徑）
Copy-Item eval\fixtures.example.json eval\fixtures.local.json
# 2. 跑（key 就是 fixtures.local.json 裡的 key）
python tools/book_eval.py --books a-200 --tasks continue
```

`fixtures.local.json` 的格式：

```json
[{"key": "a-200", "path": "E:/dev/novel1/某本書", "lang": "zh-TW", "chapter": 200}]
```

`continue` 會把**第 200 章以後的正文、章節摘要、候選稿全部遮掉**（回傳的 `masked` 就是遮了幾個檔），
模擬「寫到第 200 章」的當下，再讓模型寫第 200 章。`review` 與 `deslop` 則直接處理那一章（不遮）。

**遮掉之前會先量一次原作**，存成 `ref_*`。這件事很重要：`card_coverage` 的絕對值看起來很低
（真書實測 0.19–0.38），但人類原作自己也只有 0.25–0.45——所以要跟 `card_coverage_vs_human` 比，
不是跟 1.0 比。`issues` 同理：檢查腳本量的是訊號密度，人類長章節命中反而更多，
**只有 `issues_must`（必須修）可以跨組比較**。

## LLM 評分（可選，預設關）

```powershell
python tools/book_eval.py --provider deepseek --books a-200 --tasks continue --judge
```

- 固定 rubric（寫在 `tools/book_eval.py` 的 `RUBRIC`）：章綱貼合度、文風、連貫、可取用度各 1–5 分，
  另加一句理由。**只輸出 JSON**，解析失敗就記 `llm_ok: 0` 而不是讓整輪爆掉。
- 這些分數有噪音，所以：預設關閉、要明確加 `--judge` 才跑、容差是 0.5 分（差 0.5 分以內不算退步），
  而且**以確定性指標為主**——`llm_*` 退步時要回頭看 `style_*`／`issues`／`card_coverage` 是否也退。
- `--judge` 不能配假 provider（假 provider 的分數沒有意義），工具會直接擋。

## 假 provider 能驗到什麼

`python tools/book_eval.py` 不呼叫模型，只確認：三個任務都跑得完、提示詞組得出來、
回傳的 JSON 能解析、審查紀錄存得下來。**它的分數沒有品質意義**——假 provider 產生的文字很短，
所以 `style_*` 會是「無法量測」、`names_kept` 多半是 0。CI 用這個模式，成本是 0。

假 provider 會看**呼叫的 label** 決定回什麼：寫稿／去 AI 味／修訂回正文，其餘（結構化輸出）回合法 JSON。
（之前用「提示詞裡有沒有 novel-review」判斷，日文寫稿的提示詞剛好提到那個字串，於是把 JSON 當正文交回來。）

## 還沒做的事

- **LLM 評分的統計穩定度**：只跑一次的分數不能當結論。真要拿它做決策，至少同一份稿評 3 次取中位數，
  或固定 temperature=0；目前的做法是「有退步時回頭看確定性指標」，不單獨依賴它。
- **多章平均**：現在每本書只測一章（`chapter` 指定那一章）。要驗「整卷」的行為得排程跑多章、
  看趨勢而不是單點——那會是 P5 的事。
