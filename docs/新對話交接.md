## 驗證指令（改完一定跑）

```powershell
cd <專案資料夾>
.\.venv\Scripts\activate                       # 或 & 'C:\Users\<你>\venvs\novel-studio\Scripts\python.exe'
python tools/check_i18n.py                     # 期望：全部通過
python tools/check_parity.py --strict          # 期望：FAIL 0、WARN 0
python tools/prompt_lang_audit.py              # 期望：en/ja 都沒有中文句子
python tools/book_eval.py                      # 假 provider 冒煙，約 1 分鐘
```

花錢的驗證（只在需要判讀品質時）：

```powershell
python tools/book_eval.py --provider deepseek --books a-200,b-40,c-100 --tasks continue --repeat 3
python tools/drift.py --book <書庫>\<某本書> --from 1 --to 10
python tools/contract_audit.py --book <書庫>\<某本書>
```

## 分支與發版（2026-10-30 起）

- **`dev` 當整合分支**：功能 commit 直接進 `dev`；`main` 只放已發版的內容。
- 發版時把 `dev` 以 **squash merge** 併回 `main`（`main` 只留一顆版本 commit，PR 頁面仍會列出過程 commit）。
- **合併後固定要把 `dev` 對齊 `main`**：squash 會讓兩邊歷史分岔（內容相同但 commit 不同），不對齊的話下次 PR 會顯示「84 commits、0 file changes」。

```powershell
# 合併後
git checkout dev
git reset --hard main
git push --force-with-lease origin dev
```

- 發版流程（在 `main` 上）：
  1. 改 `app.py` 的 `VERSION` 與 `CHANGELOG.md`
  2. `git commit -m "chore(release)：x.y.z"`
  3. `git tag -a vX.Y.Z -m "Novel Studio X.Y.Z"`
  4. `git push origin main --follow-tags`
- PR 一律以 `main` 為 base，CI（`checks.yml`）綠了再合併。

## 已知陷阱（都踩過）

1. **量文風要切語言**：`shared.analyze` 依 `prompts.cur_lang()` 選分析器；直接呼叫會用錯語言（日文書被中文分析器評分）。
2. **推理模型的 `max_tokens`**：思考 token 也算在裡面，給太小會回空字串（`deepseek-flash` 實測 1200 會被吃光）。
3. **卷綱要按「章節範圍」找**：卷綱檔可能在 `大綱/` 或 `大綱/卷綱/`，不要只看資料夾。
4. **大綱排序**：中文檔名直接排序會變成「一、三、二」，要用卷號排。
5. **掃描慢**：`target_metrics` 有指紋快取，冷啟動 11 秒、熱 1.5 秒（273 章的書）。
6. **看趨勢要看平均偏離**（`style_mean_rel`），只看最大值會被「換位」騙。
7. **單次評測抖動大**：同一章 `style_max_rel` 會 0.95／1.32／2.05，判讀請用 `--repeat 3` 的中位數。
