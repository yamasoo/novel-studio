# 大綱漂移偵測（`studio/drift.py`、`tools/drift.py`）

> 卷末（或每 10 章）回頭看：**實際寫出來的**和**大綱說要寫的**差在哪。

## 四項檢查（全部不花錢）

| 檢查 | 怎麼算 | 預設門檻 |
|---|---|---|
| 章綱沒寫到 | 章綱「情節點／章末鉤子／場景」段落裡的罕見詞，有多少沒出現在正文；同時列出沒寫到的**句子**（不是二字碎片） | 覆蓋率 < 20% 才列 |
| 角色沒出場 | 章綱「出場角色」點名的人，正文完全沒提到（全名、姓氏、名字任一段都算有） | — |
| 角色消失 | 設定檔角色（只算主角／主要配角／配角）最後登場距今幾章 | 20 章 |
| 伏筆欠帳 | 追蹤/伏筆.md 裡還沒回收的伏筆，埋設距今幾章；按重要度排 | 30 章 |
| 文風漂移 | 每章偏離本書文風的倍數（`style_loop` 的偏離值） | 1.2 倍 |

## 用法

```powershell
# 最後 10 章（預設）
python tools/drift.py --book <書庫>\某本書

# 指定卷的範圍，並把報告存檔
python tools/drift.py --book <書庫>\某本書 --from 258 --to 273 --out 漂移報告.md

# 加 LLM 輕量版：只送章節摘要與卷綱（不送全文），順便產出「更新卷綱」草稿
python tools/drift.py --book <書庫>\某本書 --from 258 --to 273 --provider deepseek --plan-out 卷綱更新.md
```

## 工作台裡也有（2026-10-29 補）

總覽頁的「**卷末體檢**」會開一個**獨立頁面**（`#/b/<書>/drift`，不是彈出視窗）：

1. 選章節範圍（預設最近 10 章）→ 按「開始檢查」：本機計算，**不花錢**，畫面有秒數計時
2. 想改卷綱的話，按「產生卷綱更新草稿」：只送章節摘要與卷綱（約 1 次呼叫，30–90 秒）
3. 看過草稿滿意，按「附加到卷綱」：在該卷的卷綱檔尾加一節「卷綱更新（第 a–b 章體檢）」

**不會自動開跑**——長書第一次掃描要幾秒到十幾秒，讓你自己按比較安心。速度（273 章的書、12 章範圍）：
第一次 11.4 秒、第二次 1.5 秒（目標指標有快取，書沒改就重用）。產生草稿那段在背景執行緒跑，
伺服器不會被卡住（其他頁面照樣能用）。

三件事的檔案位置：

| 動作 | 寫到哪裡 |
|---|---|
| 草稿 | `候選/卷綱更新_第a-b章.md`（候選稿區，不是大綱） |
| 附加 | `大綱/卷綱/卷綱_第X卷.md` 的**檔尾**（只附加，不覆蓋） |
| 備份 | `.studio/備份/卷綱更新前_卷綱_第X卷.<時間>.md` |

刻意設計：**草稿先放候選區**，作者看過才附加；附加只往後加，原本的卷綱一個字都不動（實測「原本內容完整保留：True」）。
產生失敗時**不存草稿、不改卷綱**，畫面只顯示失敗原因（例如「回覆是空的（finish_reason=length）」）。

## 實測（273 章的書、第 258–273 章）

- 章綱覆蓋 36%～54%（同一位作者自己寫的章節也在這個區間，所以不是「沒照大綱」）
- 找到 2 位配角失蹤：角色丙（38 章）、角色丁（21 章）
- 未回收伏筆 300 條，最久 272 章；重要度「高」且年紀最大的幾條被列在最前面
- 文風最偏的三章都在「每千字破折號」這個指標（第 271 章 1.90 倍、第 269 章 1.20 倍）
- 章綱點名但正文沒出現的角色 7 處（含聊天室帳號，作者自己判斷是不是漏寫）

## 這是啟發式，不是判決

- 章綱覆蓋用 bigram 比對，同義改寫（「討伐」→「打倒」）會被算成沒寫到。
- 名字比對容許只寫姓或只寫名，但同名的不同角色分不出來。
- 伏筆只看「狀態」欄，狀態沒更新就會被當成欠帳。
- 所以報告是**給作者看的線索**，不是自動改稿。要它更準就得接 LLM 讀摘要（`--provider`），
  成本會上升，但目前只讀摘要、不讀全文。
