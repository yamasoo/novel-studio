# 續寫合約（`設定/續寫合約.md`）

> 目的：寫第 30 章時，「這本書已經定稿到哪」「誰死了」「哪些秘密讀者已經知道」不該散在五個表裡等人拼。

## 內容

程式從書裡既有的資料整理出六段，**不呼叫模型**：

| 段落 | 來源 | 為什麼要放進來 |
|---|---|---|
| 1. 不可變事實 | 正文章數、`設定/角色/`、`追蹤/時間線.md`、`設定/名詞表.md` | 已定稿的章節、已揭示與未揭曉的秘密，是不能推翻也不能提前說破的 |
| 2. 聲線 | `設定/文風.md` 的「基本設定」與「本書禁忌」 | 禁忌是硬規則，預算不夠時也不能掉 |
| 3. 必須承接的懸念 | `追蹤/伏筆.md` 狀態不是「已回收」的列（重要的排前面） | 續寫要知道哪些線還開著 |
| 4. 卷末承諾 | 當章所屬那一卷的 `大綱/卷綱_第N卷.md`（看 frontmatter 的「章節範圍」） | 寫稿上下文原本完全沒有卷綱，這是最容易走偏的地方 |
| 5. 禁區 | `設定/作者偏好.md` ＋ 指向 `CLAUDE.md` | 作者偏好優先於任何寫作技法 |
| 6. 作者補充 | 檔案裡 `## 作者補充` 之後的內容 | 作者自己加的規則，重產生時**原樣保留** |

## 什麼時候產生／更新

- 開始「整章自動流程」之前會自動補到最新章數。
- 拆書（逆向拆書）採用任何一組草稿之後會自動補。
- 也可以直接呼叫 API：

```powershell
# 讀（不會產生）
curl http://127.0.0.1:8765/api/books/<書名>/contract
# 產生／更新（force=true 強制重寫；否則章數沒變就不動檔）
curl -X POST http://127.0.0.1:8765/api/books/<書名>/contract -H "Content-Type: application/json" -d '{"force": true}'
```

> 變更端點要帶 `X-NS-Token`（見 S2）。用網頁介面時前端會自動帶。

## 注入方式

`studio/context.py` 的 `for_chapter()` 以 **priority 0**（跟「本書規則」「本章章綱」同一級）放進每章上下文，
所以預算再緊，合約都是最後才被砍的——實測把預算壓到 4000 token，狀態卡、伏筆、名詞表都被丟掉，
合約還在。沒有合約的書就自動略過，不會多花 token。

## 自己改的規則寫哪裡

`## 作者補充` 之後。其他地方會被重新產生覆蓋掉（因為那些段落是從資料表算出來的）。
檔案本身在「設定集」裡就看得到，跟其他設定檔一樣可以直接編輯。

## Claude Code 模式也吃得到（2026-10-29 補）

Claude Code 模式是 skills 自己讀檔，本來不看合約。現在三份 `plugin*/skills/novel-setup/references/claude-md-template.md`
的「鐵律」都多了一條：

> **續寫合約優先**：寫任何一章正文前，先讀 `設定/續寫合約.md`（工作台自動維護：章數、角色、
> 已揭曉與未揭曉的秘密、未回收伏筆、卷末承諾、禁區）。合約說不能違背的事實，優先於大綱，也優先於文風。

（英文、日文版同義。）開新書時 novel-setup 會把範本寫成那本書的 `CLAUDE.md`，之後每次對話都會載入。

## 怎麼量「零衝突」

合約講的是「不能違背的事實」，所以量法不是感覺，而是**拿設定檔回頭對正文**：

```powershell
python tools/contract_audit.py --book <書庫>\B 書
```

三種檢查（全部本機、不呼叫模型）：

| 檢查 | 判斷方式 |
|---|---|
| 提前登場 | 某章提到角色，但設定的「首次登場」在 15 章之後（差了 15 章以上才算劇透風險；只是被提到很正常） |
| 久別重逢 | 設定的「最後登場」之後 30 章又出現（只看主角／主要配角／配角；反派被回憶提起不算） |
| 未登記角色 | 章節裡出現、但 `設定/角色/` 沒有對應檔案（列在腳本輸出） |

實測結果（2026-10-29）：

| 書 | 衝突 | 看得出來的事 |
|---|---|---|
| B 書（50 章） | **0** | 作者的追蹤維護得很好 |
| A 書（273 章） | 2 | 角色戊 第 169 章就提到、設定卻寫首次登場 239（早 70 章）；角色丙最後登場記在 235、第 278 章又出現 |
| C 書（138 章） | 23 | 大量「最後登場」欄位沒更新（同一角色在 39、50、52、54… 章反覆出現，設定只記到第 3 章） |

也就是說：這支工具量的是**設定與正文的漂移**，那正是合約會拿來約束寫作的資料。

### 「連續 10 章零衝突」的正式跑法（要花錢）

```powershell
# 1) 複製一本書，不要動原稿
Copy-Item <書庫>\B 書 "$env:TEMP\十章測試" -Recurse

# 2) 用整章自動流程連寫 10 章（建議先用 config 把 autopilot_every 設成 5）
#    工作台：開這本書 → 整章自動流程 → 從第 51 章到第 60 章 → 連續寫

# 3) 寫完掃一次
python tools/contract_audit.py --book "$env:TEMP\十章測試" --from 51 --to 60
```

零衝突＝第 3 步回報 0 處。這一步還沒有人真的跑過（需要 10 章的模型費用），
所以目前只能說「工具備好了、既有書上量得出來」，不能宣稱「已驗證 10 章零衝突」。
