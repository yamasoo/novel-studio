# 自動駕駛檢查點（`studio/autopilot.py`）

> 「連續寫到最後一章」的風險：一路寫下去，第 30 章才發現文風跑掉或設定衝突，前面 20 章都要重來。
> 檢查點把品質變成流程的一部分——每 K 章停下來驗一次，不及格就停在那一章。

## 怎麼開

工作台「設定 → 整章自動流程」最下面有三個欄位（也可直接改 `config.json`）：

| 設定 | 預設 | 作用 |
|---|---|---|
| `autopilot_every` | `0`（關） | 每幾章檢查一次；`0` 表示不檢查 |
| `autopilot_stop_must` | `1` | 累計幾個「必須修」就停 |
| `autopilot_stop_style` | `2.4` | 文風偏離幾倍就停（閘門 1.2 的兩倍） |

流程要用「連續寫」（不是每章停）才會跑到檢查點。

## 檢查什麼

| 項目 | 來源 | 會停嗎 |
|---|---|---|
| 必須修 | 這幾章正文的檢查器結果（簡體字、標點、視角…） | **會**（≥ `autopilot_stop_must`） |
| 文風 | 每章偏離本書文風的倍數 | **會**（≥ `autopilot_stop_style`） |
| 漂移線索 | P5 的 `drift.findings()`（角色消失、伏筆欠帳、章綱沒寫到） | 不會，只記錄在訊息裡 |

漂移只做提示、不停下來——伏筆欠帳與久未登場的角色是全書累積的，不是這幾章造成的；
真的會擋的是「這幾章寫出來的東西有必須修的錯」與「文風整組跑掉」。

## 停下來長什麼樣

流程狀態變 `paused`，訊息像這樣：

```
檢查點沒過，先停在這裡：
- 第 12 章有「必須修」的問題共 2 項
- 文風偏離 2.61 倍（門檻 2.4；第 13 章偏在「對白比例」）

（已寫到第 13 章；處理完再按「繼續」就會接著寫。）
```

狀態裡會留 `checkpoints: [{upto, ok, stats, reasons, usage}]`，之後可以看「哪幾章過、哪幾章沒過」。
每個檢查點也會記下當時的累計用量。

## 花費統計

流程每跑完一個任務，就把該任務的 token 與費用累加進狀態的 `usage`：

```json
"usage": {"jobs": 5, "prompt_tokens": 12345, "completion_tokens": 6789, "cost": 0.0123}
```

檢查點訊息與「全部章節都完成了」都會帶一句：

```
這次流程累計 5 次模型呼叫、輸入 12,345、輸出 6,789 tokens、約 $0.0123
```

（費用是 `providers.cost_of()` 依執行者單價算的；本機 llama.cpp 之類免費的執行者費用是 0，
token 數一樣會累加。）

## 驗證（假 provider，不花錢）

| 情境 | 結果 |
|---|---|
| 每 2 章檢查、全部通過 | 5 章跑完，檢查點記在 2、4，狀態 `done` |
| 第 2 章檢查沒過 | 停在 `paused`、下一章 = 3、訊息含原因、`checkpoints: [(2, False)]` |
| `autopilot_every = 0` | 不檢查，5 章跑完 |
| 用量累加 | 兩個帶 usage 的任務 → `jobs 2、prompt 2,000、completion 1,000、cost 0.01` |
| 檢查點訊息 | 停下時多一行「這次流程累計 2 次模型呼叫、輸入 2,000、輸出 1,000 tokens、約 $0.0100」 |
| 設定頁 | 「整章自動流程」多了三個欄位（`c-ape`／`c-apsm`／`c-apss`），存檔會寫進 config |

真書實測（不花錢）：273 章的書第 258–273 章 → 必須修 0、文風最大 1.90 倍（<2.4）→ 通過；
漂移線索 15 條只寫進訊息，不會擋。
