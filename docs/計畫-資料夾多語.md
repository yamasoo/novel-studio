# 計畫：資料夾與章節檔名跟著書的語言（階段 3）

> 2026-11-07 定案。這份是實作前的最終計畫：對照表、接縫清單、里程碑、驗收標準。
> 前一版的評估（四階段、為什麼不是改幾個字串）見 `docs/開發者.md`「多語系寫作」。

## 目標

新開的書，磁碟結構用**這本書的寫作語言**：英文書是 `settings/`、`text/`、`Chapter-012_Title.md`；
日文書是 `設定/`、`本文/`、`第012話_タイトル.md`；繁中書維持現在的中文（一個字都不變）。

## 不在範圍（明確排除）

- **frontmatter 鍵**（`類型:`、`狀態:`、`章節範圍:`）與**追蹤表頭**（`編號`、`埋設章`…）仍是中文固定詞。
- **狀態詞**（`已確認`／`草稿`／`正式`）仍是中文。
- `.studio/` 內部子目錄與 `_共用/`（書庫層共用資產）仍是中文。
- **舊書遷移工具**：現有書不搬、不改名。要升級請用「匯出→開新書→匯入」。
- **換寫作語言時自動遷移**：直接禁止改語言（見下）。

## 章節檔名規則

- zh-TW：`第012章_標題.md`（現況不變）
- en：`Chapter-012_Title.md`
- ja：`第012話_タイトル.md`

解析要**同時接受三種樣式**（舊書、混用、模型寫錯都能讀）：

```python
paths.chapter_name(no, title, lang) -> str
paths.chapter_no(filename) -> int | None      # 三種樣式都認，回傳章號
paths.sort_key(filename) -> (int, str)        # 章號優先，修掉「一、三、二」的字串排序
```

## 提示詞與檔案區塊協議

模型目前被直接告知「寫 `<<<檔案 設定/角色/X.md>>>`」。做法：

1. 提示詞不再寫死路徑，改成注入 `paths.prompt_hint(book_dir)`（列出這本書實際的資料夾名）。
2. `native_files` 收到相對路徑時先過 `paths.to_book(book_dir, rel)`：
   - 已經是本書語言 → 原樣；
   - 是另一種語言的同名路徑 → 映射成本書語言（容忍模型寫中文）；
   - 都不認識 → 拒絕，並在結果列出「不允許寫入這個位置」。
3. 任務結果顯示實際寫入的相對路徑（使用者看到的是本書語言的）。

## tools 與 CI

- `tools/check_parity.py` 的 `demo_units()`：**不能取消比對**，改成「先用 paths 把三本示範書的路徑正規化成邏輯名，再比對邏輯檔案集」。
- 新增 `tools/check_paths.py`：掃 `app.py`、`studio/`、`static/`、`tools/` 的硬編碼路徑字面值，`studio/paths.py` 以外出現就 FAIL。**這是防止地圖腐化的唯一機制，要進 CI。**
- `book_eval`／`prompt_lang_audit`：fixture 路徑改由 `paths` 取得；三語冒煙要綠。

## 相容性

- `paths.detect(book_dir)`：用「哪一張表的頂層資料夾存在」判斷結構語言，結果快取（提供 `clear_cache()` 給測試）。
- `paths.of(book_dir)`：優先結構偵測，偵測不到才用 `lang.book_lang()`；都不符就當 zh-TW（維持舊行為）。
- 寫入一律用偵測到的結構語言那張表 → 舊書、手改過的書都不會壞。
- `lang.set_book_lang()` 對「已有結構」的書改成拒絕並回一句人話；建書時才決定語言。

## 風險與回滾

| 風險 | 影響 | 緩解 |
|---|---|---|
| 提示詞／檔案區塊協議漂移，模型寫錯資料夾 | 設定集與大綱寫不進去 | `prompt_hint` 注入＋`to_book()` 容忍映射＋結果顯示實際路徑 |
| 章號解析改壞（排序、跳號、修訂檔名） | 一章被讀成兩章或漏章 | 三語 round-trip 測試＋舊書檔名回歸；改變集中 M4 一個 commit |
| `demo_units` 為了過關而放寬 | 失去 parity 守門 | 只准「正規化後比對」，不准刪檢查 |
| `is_book`／掃描判斷錯 | 書架看不到書（最痛） | 結構偵測＋用全部現有書當回歸清單；M2 先行上線觀察 |
| 換語言被禁止 | 使用者不習慣 | UI 文案三語＋「要換語言請開新書」的明確說明（M8） |

回滾：M1–M7 每個都是獨立 commit、預設行為與現況相同，出問題 revert 那一個即可；**唯一的行為切換點在 M8（示範書換結構）**，往前都是「加能力、不改行為」。

## 不在這個計畫裡、但之後會遇到的

- frontmatter 鍵與追蹤表頭多語（等於重做 `jsonkeys`／`enums`／`upsert_table` 的資料契約）。
- 舊書一鍵升級成多語結構（要寫遷移工具＋dry-run＋回復方案，風險最高，建議永遠用「匯出→新書→匯入」代替）。
