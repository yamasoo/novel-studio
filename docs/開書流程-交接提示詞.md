## 背景（一句話）
使用者實測《太空牛仔》後回報：進入章節寫作很順，但「開新書 → 訪談 → 然後呢」不順。用他的 82 筆任務紀錄（`E:\dev\novel1\太空牛仔\.studio\jobs`）還原後確認：訪談 3 分鐘就產出檔案，但有 28 個叫「回覆」的任務、55 分鐘花在找路。原因與修法已寫進規格書。

## 已定案的決策（不要再問使用者）
1. 訪談在面板用**可點選項**問：一輪最多 4 題、每題按鈕＋可自由輸入。
2. 訪談後總覽頁要有「開書進度」與**唯一一顆 primary ＝下一步**（故事核心 → 全書大綱 → 第一卷卷綱 → 前 10 章章綱 → 寫第 1 章）。
3. 「要接著做什麼？」回覆框**保留為主要互動**，只改提示文字與定位說明。
4. 參考書／骨架開書收進開新書表單的「進階選項」；預設只看到 書名／一句話／語言。
5. 不做：多書同時訪談、訪談中途換執行者、改動章節寫作與整章自動流程、改 provider 機制。

## 要做的五件事（細節在規格書 §5）
1. `static/page_shelf.js:46-96` 開新書表單縮成 3 欄，其餘收進 details；建立後帶狀態讓總覽知道「剛建立」。
2. `static/page_overview.js:56-92` 拆成三態（訪談進行中／訪談中斷／真的不是小說專案），移除重複的 primary；`:122-137` 加開書進度步驟條與下一步卡。
3. `studio/native_files.py:292-303` + `studio/prompts/{zh_TW,en,ja}.py`：setup_new 改成 `c.job.ask(...)` 走固定題庫（兩輪 8 題＋可跳過的第三輪），再一次呼叫模型產出 CLAUDE.md／設定/故事核心.md／設定/文風.md。
4. `ns_jobs.py:345-358`：任務 running 且有真實 ask 時，把回覆轉給 `job._deliver_reply(ask_id, text)`（fekit 已支援，見 `vendor/fekit/py/fekit/jobs.py:510-515`），不要一律開新任務；`app.py:2501-2502` 的 409 只留給「沒有 ask 在等」。
5. `static/app.js` 的 `Panel.finish`：setup_new 完成時顯示「開書報告」卡（檔案清單由程式檢查檔案存在＋frontmatter，不信模型自述），並附一顆「下一步」。

## 硬性限制
- **檔案寫入驗證**：報告卡上的「已建立」必須是後端實際檢查檔案的結果。
- **Claude Code 模式**沒有 ask（`studio/runner.py:313-326` 是 `claude -p` 非互動）：該模式要顯示「這個模式沒有選項按鈕，建議切到 API 執行者」並允許照舊文字回覆，不能壞掉。
- 已有 CLAUDE.md 的舊書，總覽行為必須完全不變（用《太空牛仔》和《退婚之後（示範）》各開一次確認）。
- 不動 `正文/`、`大綱/` 的既有檔案；不要跑 `git` 以外的破壞性指令。

## 驗收（規格書 §6 九條，逐條給證據）
1. 開新書預設 3 欄，不展開進階也能開書。
2. 開書後 2 秒內總覽顯示「訪談正在進行／打開右側面板」，且沒有第二顆 primary。
3. 訪談全程可只用點按鈕走完兩輪，第三輪可跳過。
4. 任選「跳過，你決定」→ 檔案有內容，報告標「（預設）」。
5. 訪談完成後面板出現報告卡，列出實際寫入的檔案；缺的標「待補」。
6. 報告卡的下一步＝總覽 primary＝同一個動作。
7. 五步都完成後 primary 才變「寫第 1 章」。
8. 非訪談任務的回覆框提示為「補充需求…」。
9. 舊書總覽不變。
