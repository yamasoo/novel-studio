# Routing problems and fixing them

## 1. Order of fixes

When a passage has several kinds of problems, **fix the lower layer first, then the surface**:

1. **Plot logic and character consistency** (cause and effect, motive, state, goal)
2. **Transitions, dialogue, chapter-ending hand-off** (the bridges between scenes)
3. **Prose and AI voice** (wording, sentence patterns, stock phrases)

Do not mistake a structural problem for a style problem: a passage that reads "hollow" may have no change in the scene at all, and swapping adjectives will not save it.

## 2. How to fix each kind of problem

| Problem | What to add first |
|---|---|
| A goal suddenly changed | The trigger for the new goal; why the old goal gave way |
| Emotion flipped too fast | A trigger object; at least one beat of reaction in between |
| A relationship reset at the click of a button | An in-between step of easing or worsening |
| Injury or fatigue vanished | Bodily feedback (pain, slowness); limits on action |
| Doesn't sound like this person | Rework sentence pattern, way of applying pressure and diction from the voice card |
| A character knows what he shouldn't | Delete it, or add the way he found out |
| Setting contradiction | Fix the setting to match the written text, or change the text; ask the author first |
| The reader gets lost | Add time, place and viewpoint to the transition line |
| The hook was not caught | Add the catch at the start of the next chapter, or adjust the previous ending |
| Early spoiler | Delete it; use a detail the characters can sense but do not spell out |
| Foreshadowing left hanging | Schedule a light touch in the next chapter's card |

## 3. Who fixes it

- **Chapter-text problems** → novel-write's revision flow. The review itself does not edit the text unless the author says "just fix it".
- **Setting problems** → novel-bible (ask the author first on conflicts).
- **Tracking errors** (tracking disagrees with the text) → you may correct tracking directly, with the text as the authority. List what you changed in the report.
- **Card problems** (later cards contradict facts already written) → novel-outline.

## 4. Report format

```
## Chapter {N} (or chapters {N}-{M}) review result

Overall: {one-sentence conclusion, e.g. "Passes, with two suggested fixes" or "Does not pass; the main problem is character state"}

### Must fix
1. [Chapter {N} · {location, e.g. the scene where Callum saves someone}] {problem}. Grounds: {the setting or earlier passage}. Suggestion: {how to fix it}
2. ...

### Should fix
1. ...

### Notes
- ...

### State of the database
- Tracking data: {in sync / behind through chapter X / found N mismatches, fixed: ...}
- Foreshadowing: {foreshadowing that needs attention, with its story tag}
- Absent too long: {characters}

Suggested next step: {e.g. "Shall I hand the two must-fix items to the revision flow?"}
```

Make the report concrete enough to act on: point to the location, state the grounds, give the fix. Do not just write "the character is a bit inconsistent".
