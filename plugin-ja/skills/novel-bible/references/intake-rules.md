# 設定を取り込む規則

## 1. 三つの源、一つの入口

| 源 | 例 | 行き先 |
|---|---|---|
| 作者が書いた | 作者が人物紹介を貼る、またはファイルを直接編集する | 作者がはっきり「これで決まり」と言えば正式。そうでなければ一度「このまま確定しますか」と尋ねる |
| 会話から抽出 | 世界観を三十分話し合い、「さっき決まったことを整理して」 | 作者が**はっきり同意した**ものは正式、話し合っただけで決めていないものは草稿 |
| AI が生成 | 「脇役を 5 人出して」「この国の税制を設計して」 | 必ず先に `設定/草稿/` へ。作者が確認して初めて正式 |

「確認済み」かどうか判断できないときは、草稿に入れる。草稿に誤って入れる損は小さいが、正式な設定に誤って入れると本文を汚す。

## 2. 会話から抽出する方法

1. 会話（または作者が貼った記録）を振り返り、出てきた設定の要素をすべて挙げる。
2. それぞれに印を付ける：
   - **決定**：作者が「いいね」「それで」「気に入った」と言った、または自分で出して覆されなかった。
   - **検討中**：選択肢がいくつか出て選ばれなかった、または作者が「考えさせて」と言った。
   - **却下**：作者が否定したもの。
3. 覆されたものは**最後**の発言が優先。
4. 決定したものは正式なファイルに書き、検討中のものは候補の選択肢を添えて草稿に書く。却下されたものは書かない（作者が「やらないこと」を記録したいなら、名詞表の注意欄か人物の備考に入れる）。
5. 報告では表で示す：何を正式にしたか、何を草稿に回したか、何を取らなかったか。

## 3. 草稿から正式へ

作者が「草稿の X は決まった」「これで全部決まり」と言ったとき：

1. 草稿ファイルを読み、正しい雛形（`_範本/角色.md` など）で形式を整える。
2. フロントマターの `狀態` を `正式` にして、対応する正式なフォルダへ移す。
3. 既存の正式な設定との衝突（同名、矛盾する規則、合わない関係）を確かめる。衝突があれば先に作者に尋ねる。
4. 新しい用語を名詞表に登録する。
5. 草稿ファイルを消す。

## 4. 章の後の登録（novel-write の申告に続けて）

章を書き終えると、novel-write が「書いて報告する」新しいものを挙げる。それをデータベースに登録する：

| 新しいものの種類 | 登録先 |
|---|---|
| 名前のある脇役 | `設定/角色/{名前}.md`（定位：配角。本文に出たことだけを埋め、他の欄は空にする） |
| 新しい勢力 | `設定/勢力/{名前}.md` |
| 新しい規則、能力の見せ方、地理や制度の細部 | 対応する `設定/世界觀/{項目}.md` に規則を足す |
| 新しい用語や呼称 | `設定/名詞表.md` |
| 新しい伏線、関係、約束 | これらは「事実」であり、novel-write が `追蹤/` に書く。ここでは扱わない |

登録するときは、**章の本文がすでに示した情報だけ**を書く。脇役の生い立ちを作らない。足したければ、作者に尋ねるか草稿に入れる。

## 5. 衝突の扱い

二つの設定が矛盾するとき：

1. どちらかを選んで自分で直さない。
2. 挙げる：矛盾する二か所（ファイル、元の文言）と、それぞれを引用している書き終えた章。
3. 作者に 2～3 個の選択肢とおすすめを出す。たいていは「すでに本文にあるほうに合わせる」をおすすめする。読者はもう見ているからだ。
4. 作者が決めたら設定ファイルを直す。本文を直す必要があれば、novel-write の改稿手順に回す。

## 6. 名前の付け方の規則

- ファイル名は設定の最もよく使う名前：例 `伊音.md`、`波止場組合.md`、`力の体系.md`。
- 別名はフロントマターの `別名` に入れる。別名のために別ファイルを作らない。
- 同名の別人は修飾語を足す：例 `三浦（船具商の番頭）.md`。
- 表記は本全体で統一する（たとえば「港」「みなと」のどちらかに決め、名詞表に書く）。人名の表記ゆれ（旧字体・新字体、かなと漢字）も名詞表で固定する。
