# 問題の振り分けと直し方

## 1. 直す順番

一か所に何種類かの問題があるときは、**下の層から先に直し、表面は後**にする：

1. **筋の論理と人物の整合**（因果、動機、状態、目標）
2. **場面転換、会話、章末の引き継ぎ**（場面をつなぐ橋）
3. **文章と AI 臭**（言葉、文型、決まり文句）

構造の問題を文体の問題と取り違えない：読んで「空っぽ」に思える箇所は、場面にそもそも変化がないのかもしれず、形容詞を替えても救えない。

## 2. 問題の種類ごとの直し方

| 問題 | 先に足すもの |
|---|---|
| 目標が急に変わった | 新しい目標のきっかけ。古い目標がなぜ道を譲ったか |
| 感情が急に裏返った | きっかけとなる物。間に少なくとも一拍の反応 |
| 関係がボタンを押したようにリセットされた | ゆるむ、または悪くなる途中の段階 |
| 怪我や疲労が消えた | 身体からの反応（痛み、鈍さ）。行動の制限 |
| この人らしくない | 声カードから、文型、圧のかけ方、語彙を作り直す |
| 人物が知るはずのないことを知っている | 消すか、知った経路を足す |
| 設定の矛盾 | 書かれた本文に合わせて設定を直すか、本文を変える。先に作者に聞く |
| 読者が迷う | 転換の一文に時間、場所、視点を足す |
| 引きが受け止められていない | 次の章の冒頭に受け止めを足すか、前の終わりを調整する |
| 早すぎるネタばらし | 消す。人物が感じ取れるが口に出さない細部を使う |
| 放置された伏線 | 次の章の章綱に、軽く触れる予定を入れる |

## 3. 誰が直すか

- **本文の問題** → novel-write の改稿手順。作者が「そのまま直して」と言わない限り、審査自身は本文を直さない。
- **設定の問題** → novel-bible（衝突は先に作者に聞く）。
- **追蹤の誤り**（追蹤が本文と食い違う） → 本文を正として、追蹤を直接直してよい。直したことは報告に挙げる。
- **章綱の問題**（後の章綱が、すでに書かれた事実と矛盾する） → novel-outline。

## 4. 報告の形式

```
## 第{N}章（または第{N}～{M}章）の審査結果

全体：{一文の結論。例：「合格。修正案が 2 点あります」「不合格。主な問題は人物の状態です」}

### 必ず直す
1. 【第{N}章・{場所。例：ミラが人を助ける場面}】{問題}。根拠：{基づく設定または前の本文}。提案：{直し方}
2. ...

### 直した方がよい
1. ...

### 注意
- ...

### データベースの状況
- 追蹤データ：{同期済み／第X章まで遅れている／N 件の不一致を発見、修正済み：…}
- 伏線：{注意が必要な伏線と、その物語上の呼び名}
- 長く登場していない：{人物}

次の提案：{例：「必ず直す 2 点を改稿の手順に回しましょうか」}
```

報告は実行できる具体性を持たせます：場所を示し、根拠を述べ、直し方を書く。「人物が少しぶれている」のような曖昧な書き方は避けます。
