# CLAUDE.md の雛形

novel-setup がプロジェクトを作るとき、下の `---範本開始---` から `---範本結束---` までの間を書籍フォルダの `CLAUDE.md` として書き出し、`{...}` をインタビューの結果に置き換えます。簡潔にしてください。このファイルは会話を始めるたびに読み込まれるので、長いと文脈を無駄にします。

---範本開始---

# 『{書名}』執筆プロジェクト

{一文の引き}

## 基本
- ジャンル：{ジャンル}　掲載先：{掲載先}　想定の分量：{分量}
- 視点：{視点と時制}
- 一章の長さ：{幅。例：2,000～3,000 字}
- 言語：日本語。表記は文風ファイルに従う（会話は「」、引用は『』、三点リーダーは「……」、ダッシュは「――」）。別の言語での入力は、日本語にしてからファイルに入れる。

## どこに何があるか
- 設定（固定）：`設定/`　故事核心、文風、作者偏好、名詞表、世界観、人物、勢力。未確認のものは `設定/草稿/`
- 計画（まだ起きていない）：`大綱/`　全書大綱、卷綱、章綱
- 事実（すでに起きた）：`追蹤/`　狀態卡、角色狀態、伏筆、時間線、章節摘要
- 本文：`正文/第NNN章_<題名>.md`
- 空の雛形：`_範本/`

（フォルダ名とファイル名は中国語のまま。工作台のプログラムが読みます。）

## 鉄則
1. 計画と事実を分ける：大綱は計画、追蹤は事実。章の本文が確定する前に追蹤を変えない。
2. 草稿と正式を分ける：本文が引用できるのは正式な設定だけで、`設定/草稿/` は使わない。
3. 章綱は、その章の唯一の筋の設計図。本文は、章綱で決まった結果を変えない。
4. 書くときは `追蹤/時間線.md` の「読者がいま知っていること」に従い、先にばらさない。
5. **続き書きの契約が最優先**：どの章の本文を書く前にも `設定/續寫合約.md` を読む（アプリが自動で更新：章数、人物、明かした秘密と未公開の秘密、未回収の伏線、巻末の約束、禁止事項）。契約が「変えてはいけない」とした事実は、大綱よりも文体よりも優先する。

## 新しく出てくるものの三段階
書いたり計画したりする中で出てきた人や物事は、段階に分けて扱う：
- **そのまま書く**：通行人、一度きりの小道具、場面の細部、地名の細かな描写。登録は不要。
- **書いて報告する**：名前のある脇役、新しい勢力、新しい規則や能力の見せ方、新しい伏線、新しい関係や約束、繰り返し出る場所や物。書いてよいが、報告に挙げ、データベースに登録する。
- **先に作者に聞く**：本筋の新しい出来事や大きな転換、反則級の能力や力の体系の規則、真相の開示や重要な伏線の回収、章綱で決まった結果や人物の決断の変更、既存の設定と衝突すること。一人で決めず、止まって尋ねる。
- 迷ったら：書いているときは「書いて報告する」、計画しているときは「先に作者に聞く」として扱う。

## 文体の優先順位
書き方の問題では、次のうち、立場がはっきりしている最初のものに従う：
**今回の作者の依頼 > `設定/文風.md` > `設定/作者偏好.md` > 一般的な執筆ルール**
一般のルールが「必ず」「絶対に」と言っていても、作者のはっきりした選択を覆せない。ただし文体は、筋の事実、情報の境界、章綱で決まった結果を変えられない。

## 進め方
- 使うスキル：開書と文体 → novel-setup、設定データベース → novel-bible、大綱と章綱 → novel-outline、章と改稿 → novel-write、整合性の審査 → novel-review、AI 臭抜き → novel-deslop。
- 本文を書くには、作者がどの章かを言うか「続けて」と言うこと。既定は一章、多くても一度に 3 章まで。
- 作者が「続けて」「それで」としか言わないときは、範囲を広げない：計画の段階では計画だけを進め、勝手に本文を書き始めない。
- 作者への報告は平易な言葉で：何を書いたか、何を決める必要があるか、次は何か。尋ねられない限り、ファイル名やフィールド名は出さない。
- 作者が長期の好み（「今後は…」「覚えておいて」）を述べたら、`設定/作者偏好.md` に記録する。一回限りの依頼は実行するだけで記録しない。
