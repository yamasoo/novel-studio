# 章を書き終えた後の書き戻し

章の本文が確定したら、下のファイルを順に更新します。原則：**本文で本当に起きたことだけを書く。** 章綱が計画していても本文が届けなかったことは、追蹤に書きません。

ファイル名、フォルダ名、フロントマターのキー、表の見出しは、雛形どおり中国語のままにします。中に書く内容は日本語です。

## 1. 章の要約（新規ファイル）

`追蹤/章節摘要/第NNN章.md`。`_範本/章節摘要.md` から。300～600 字：何が起き、状況がどう変わり、何が・誰が新しく現れ、章がどこで止まるか。実際の字数をフロントマターに入れる。

## 2. 狀態卡（最新に上書き）

`追蹤/狀態卡.md` は「いま」の写真：
- **1 目前位置**：この章の終わりの巻・章、作中の時間、場面に変える。
- **2 主線進度**：進んでいれば変える。
- **3 在場角色**：この章の終わりに物語の中心にいる人物。去った人は消す。
- **4 下一章承諾**：この章の終わりが残す引きと、受け止めるべきことに置き換える。この章が前の章の承諾を果たしていれば、それは消す。
- **5 長期約束**：新しいものを足し、解けたものを消す。
- **6 連續性風險**：この章で生じた間違えやすい細部（新しい怪我、新しい誤解、手を移った物）を足し、もう危険でないものを消す。
- **7 活躍伏筆**：伏筆の表の「推進中」と、近く扱うものに合わせる。
- フロントマターの `更新至` をこの章にする。

古い内容を消すのは必須で、下に足していくだけにしない。ファイル全体が 3,000 字を超えそうなら、次の章に最も影響しない古い内容から削る。

## 3. 角色狀態（変化したときだけ変更）

`追蹤/角色狀態/{人物名}.md`：
- **この章で変化した**人物だけを更新する：居場所、目標、身体、感情、能力と手持ち、関係、知っている秘密、未解決のこと。
- 名前のある重要人物が初めて出たら、`_範本/角色狀態.md` から新しいファイルを作る。
- この章に出た人物は `最後登場` をこの章に、更新した人物は `更新至` をこの章にする。
- 「知っている秘密」は厳密に：その人物が**作中で**すでに知っていることだけを書き、読者だけが知ることは書かない。

## 4. 伏筆の表

`追蹤/伏筆.md`：
- **新しく仕込んだ**：次の番号（F と 3 桁）で行を足し、状態を 已埋 にする。
- **進めた、または軽く触れた**：`最後出現` をこの章にし、状態を 推進中 にする。
- **回収した**：状態を 已回收 に、`最後出現` をこの章にする。
- 章綱が仕込むつもりだったが本文に書かなかった伏線は登録しない。

## 5. 時間線

`追蹤/時間線.md`：
- この章の重要な出来事、またはこの章で初めて触れた過去の出来事ごとに、行（E と 3 桁）を足す。
- 「讀者目前知道」は、この章を読んだ後で読者がどこまで知っているかを書く。
- この章が古い出来事の真相を明かしたときは、その行の「讀者目前知道」と「揭示章」を更新する。

### 読者認知の台帳

`追蹤/讀者認知.md`（下の場合に当てはまらなければ飛ばす。ファイルがないとき：時間線が 15 行未満の新しい本なら `_範本/讀者認知.md` から作る。すでに多くの章を書いた古い本なら自分では作らず、この節を飛ばして、工作台の「時間線から作る」が使えると報告で伝える）：
- 読者が答えを待ち始めるもの（違和感に気づく、未解決の疑問）：読者が抱く疑問の形で 懸念 の行（R と 3 桁）を足す。
- 章が意図して読者に誤解させること：読者が信じている版を書いた 誤認 の行を足す。
- 読者は知っているが、一部の人物は知らない重要情報：誰が知らないかを書いて 已知 の行を足す。普通の出来事は 已知 として登録しなくてよい。
- この章が古い懸念や誤認を明かしたり解いたりしたら、その行の回收章にこの章を入れる。
- 「作者真相」は任意：章綱か時間線に答えが書かれているときだけ埋める。分からなければ空にして、作り話はしない。

### 人物関係

`追蹤/關係.md`（この章で関係が変わらなければ飛ばす。ファイルがないとき：第 15 章より前の新しい本なら `_範本/關係.md` から作る。すでに多くの章を書いた古い本なら自分では作らず、この節を飛ばして、工作台の「人物ファイルから作る」が使えると報告で伝える）：
- 一方向を一行に：「AからB」と「BからA」は別。片方の見方だけが変わるなら、その行だけ触る。「關係」は役割や立場（師弟、盟友、債権者）、「態度」はその人が相手に抱く感情と温度（信頼、警戒、好意）。
- **この章で初めてはっきりした関係**：行を足し（L と 3 桁）、起始章をこの章にし、變化原因の欄に、この章のどの出来事かを書く。
- **この章で変わった関係**：古い行の結束章にこの章を入れ（内容は直さない）、新しい關係と態度で新しい行を開き、起始章をこの章にして原因を書く。古い行を上書きせず、履歴を残す。
- 変わらない関係には触れない。人物ファイルの正式な名前を使う。

## 6. 設定の登録（「書いて報告する」段階の新しいもの）

novel-bible の取り込み規則に従う（novel-bible が入っていれば、その references/intake-rules.md の第 4 節を読む）：
- 名前のある脇役 → `設定/角色/`（本文に出たことだけを書く）
- 新しい勢力 → `設定/勢力/`
- 新しい規則や能力の見せ方 → 該当する `設定/世界觀/` のファイル
- 新しい用語や呼称 → `設定/名詞表.md`

## 7. 章綱の状態

この章の章綱のフロントマターの `狀態` を `已寫` にする。本文が章綱から外れた場合（作者が同意した変更など）は、章綱の備考の下に、実際の扱いを一行で書く。

## 8. バージョン管理

プロジェクトが git を使っていれば、書き戻しが終わったら一度コミットする：`第NNN章 <題名>`。作者に先に聞く必要はない（開書のときに git に同意している）。作者が git に同意していなければコミットしない。

## 改稿時の書き戻し

書き終えた章を直した後：
1. その章の要約を書き直す。
2. 前後を比べて、**変わった事実**（誰が何を知っているか、誰が怪我をしたか、物がどこへ行ったか、関係の変化、仕込んだ・回収した伏線）を見つける。
3. 伏筆の表と時間線の関連する行を直す。
4. 狀態卡、角色狀態、關係の表は、その事実が**いまも**有効なときだけ変える。例：第 5 章の怪我を変えても、人物が第 20 章までにとうに治っていれば、現在の角色狀態は変えなくてよい。
5. **影響を受けそうな後続の章**を挙げる：後の要約と本文で、これらの事実に触れる箇所を探し、一覧を作者に渡して、一緒に直すか novel-review に渡すかを尋ねる。
