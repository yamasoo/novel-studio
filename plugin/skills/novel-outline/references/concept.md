# 故事核心診斷

在寫大綱之前，先確認這個點子撐得起預定的篇幅。點子壓不出最小骨架時，不要急著排章節。

## 一、最小骨架（五個問題）

1. **主角是誰？** 一句話：身分＋處境。
2. **他想要什麼？** 具體、可被阻止、讀者看得見進度的目標。
3. **什麼擋住他？** 對手、制度、自身缺陷、環境。
4. **讀者為什麼想看他贏（或掙扎）？** 共情點：委屈、不公、渴望、反差。
5. **故事怎麼一直跑下去？** 故事引擎（見下）。

五題中有任一題答不出來，先跟作者把它聊清楚。

## 二、賣點：讀者到底在消費什麼

網文讀者是為了某種反覆出現的情緒滿足而追更。要說得出這本書主要提供哪 1～3 種：

| 賣點類型 | 讀者得到的感受 | 典型手法 |
|---|---|---|
| 打臉逆襲 | 痛快 | 被輕視 → 實力展現 → 旁人反應 |
| 扮豬吃虎 | 期待＋痛快 | 主角實力被低估、讀者知道真相、壓抑累積後爆發 |
| 升級成長 | 成就感 | 清楚的等級、每階段都有可見的收穫 |
| 感情拉扯 | 心動、意難平 | 靠近與阻礙交替、誤會與和解 |
| 解謎懸疑 | 好奇、智性滿足 | 線索公平地鋪在前面、揭曉時「原來如此」 |
| 經營種田 | 安心、累積感 | 從無到有、數字與規模的成長 |
| 身分反差 | 驚喜 | 隱藏身分逐層揭露、旁人認知的翻轉 |

賣點決定節奏：打臉文的釋放要密，懸疑文的線索要勻，感情文的拉扯要有來回。

## 三、故事引擎

故事引擎是「每隔一段就會自然產生新衝突」的機制。沒有引擎的長篇，寫到二三十章就會開始找不到事做。

好的引擎通常有這些特徵：
- **可重複**：同一種機制能套在不同場景、不同對手身上。
- **會升級**：每次重複，賭注或舞台變大。
- **連著主線**：每一輪的結果推動主線前進一步。

例：
- 「每解開玉珮的一層封印，就會引來更強的追殺者，同時揭露一段身世」——可重複、會升級、連主線。
- 「主角很強，到處打敗壞人」——可重複，但不升級也不連主線，很快會疲乏。

## 四、讀者契約

讀者契約是開篇向讀者做出的承諾，後面要守住：
- **類型承諾**：標成甜寵就不能突然虐到底。
- **主角承諾**：開篇展現聰明，後面就不能為了劇情需要變笨。
- **節奏承諾**：開篇爽點密集，後面不能突然十章沒有釋放。

把契約條列寫進 `設定/故事核心.md`。寫大綱和章綱時，對照契約檢查有沒有違約。

## 五、篇幅判斷

| 點子特徵 | 適合 |
|---|---|
| 一個核心反轉、一段關係的變化 | 短篇（3 萬字內） |
| 一個完整的成長或復仇弧線，舞台不太需要擴大 | 中篇（10～30 萬） |
| 有升級台階、舞台會一層層擴大、有多條支線可輪替 | 長篇（50 萬以上） |

作者想寫長篇但點子只夠中篇時，誠實說出來，並提出擴充方向（加升級台階、加支線、擴大舞台），讓作者決定。

## 六、診斷輸出格式

做完診斷給作者看這幾項，每項一兩句：
1. 最小骨架（五題答案）
2. 主要賣點
3. 故事引擎，以及你對它能跑多遠的判斷
4. 建議篇幅
5. 目前的缺口與建議（最多三條，按重要性排序）
