# 問題分流與修正

## 一、修正的優先順序

一個段落同時有多種問題時，**先修底層，再修表層**：

1. **劇情邏輯、人物一致性**（因果、動機、狀態、目標）
2. **轉場、對白、章末承接**（場景之間的橋）
3. **文字與 AI 味**（用詞、句式、套話）

不要把結構問題誤當成文風問題修：一段讀起來「很空」，可能是因為這場戲根本沒有變化，換掉形容詞也救不了。

## 二、各類問題的修法

| 問題 | 優先補什麼 |
|---|---|
| 目標忽然換了 | 新目標的觸發事件；舊目標為什麼讓位 |
| 情緒翻面太快 | 觸發物；中間至少一拍反應 |
| 關係一鍵重置 | 緩和或惡化的中間一步 |
| 傷病疲勞消失 | 身體回饋（疼痛、遲緩）；行動上的限制 |
| 說話不像這個人 | 照聲音卡改句式、施壓方式、用詞 |
| 角色知道不該知道的事 | 刪掉，或補上他得知的途徑 |
| 設定矛盾 | 以已寫正文為準修設定，或改正文；先問作者 |
| 讀者迷路 | 轉場句補時間、地點、視角 |
| 鉤子沒接住 | 下一章開頭補承接，或調整上一章結尾 |
| 提前洩底 | 刪除，改成角色可感知、但不說破的細節 |
| 伏筆晾太久 | 在下一章章綱排一次輕觸 |

## 三、誰來修

- **正文問題** → 交給 novel-write 的改稿流程。審查本身不直接改正文，除非作者說「直接幫我修」。
- **設定問題** → novel-bible（衝突要先問作者）。
- **追蹤資料錯誤**（追蹤和正文不符）→ 可以直接修正追蹤，以正文為準。修完在報告中列出改了什麼。
- **章綱問題**（後續章綱與已發生事實矛盾）→ novel-outline。

## 四、報告格式

```
## 第{N}章（或第{N}～{M}章）審查結果

整體：{一句話結論，例：「通過，有兩處建議修」或「不通過，主要問題在人物狀態」}

### 必須修
1. 【第{N}章・{位置，例：沈既白救人那段}】{問題}。依據：{設定或前文出處}。建議：{怎麼修}
2. ……

### 建議修
1. ……

### 提醒
- ……

### 資料庫狀況
- 追蹤資料：{已同步／落後到第X章／發現N處不符，已修正：……}
- 伏筆：{需要注意的伏筆，附故事標籤}
- 久未出場：{角色}

下一步建議：{例：「要我把必須修的兩處交給改稿流程修掉嗎？」}
```

報告要具體到能直接動手：指出位置、說明依據、給出修法。不要只寫「人物有點不一致」。
