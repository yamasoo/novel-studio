# CLAUDE.md 範本

novel-setup 建專案時，把下面 `---範本開始---` 到 `---範本結束---` 之間的內容寫成書目錄下的 `CLAUDE.md`，並把 `{...}` 換成訪談結果。保持精簡：這份檔案每次開對話都會載入，太長會浪費上下文。

---範本開始---

# 《{書名}》寫作專案

{一句話鉤子}

## 基本設定
- 題材：{題材}　平台：{平台}　預計篇幅：{篇幅}
- 視角：{視角}
- 每章字數：{字數範圍，例：2500～3500 字}
- 語言：台灣繁體中文。用語、標點依台灣習慣（引號「」『』、刪節號……、破折號——）。輸入若是簡體，一律轉成繁體再寫入檔案。

## 資料在哪裡
- 設定（靜態）：`設定/`　故事核心、文風、作者偏好、名詞表、世界觀、角色、勢力；未確認的在 `設定/草稿/`
- 計畫（未發生）：`大綱/`　全書大綱、卷綱、章綱
- 事實（已發生）：`追蹤/`　狀態卡、角色狀態、伏筆、時間線、章節摘要
- 正文：`正文/第NNN章_章名.md`
- 空白範本：`_範本/`

## 鐵律
1. 計畫與事實分開：大綱是計畫，追蹤是事實。正文定稿前不改追蹤。
2. 草稿與正式分開：正文只能引用正式設定，不能引用 `設定/草稿/`。
3. 章綱是這章唯一的劇情藍圖。正文不擅自改變章綱已定的結果。
4. 寫作時遵守 `追蹤/時間線.md` 的「讀者目前知道」，不提前洩底。

## 新增物三級
寫作或規劃時多出來的人事物，照下面分級處理：
- **直接寫**：路人、一次性小道具、場景細節、地名細部。不用登記。
- **寫了要報**：具名配角、新勢力、新規則或能力表現、新伏筆、新關係或承諾、會重複出現的地點或物品。可以寫，但寫完要列在匯報裡並登記進資料庫。
- **先問作者**：新主線事件或大反轉、金手指／力量體系的規則、揭開真相或回收重要伏筆、改變章綱已定的結果或人物決定、與既有設定衝突的內容。不能自己決定，先停下來問。
- 拿不準時：寫作時當「寫了要報」，規劃時當「先問作者」。

## 文風優先順序
同一個寫法問題，依序取第一個有明確說法的：
**作者這次的要求 ＞ `設定/文風.md` ＞ `設定/作者偏好.md` ＞ 通用寫作規則**
通用規則寫「必須」「禁止」也不能壓過作者的明確選擇。但文風不能改變劇情事實、資訊揭露邊界和章綱結果。

## 工作方式
- 用到的 skill：開書與文風 → novel-setup；設定資料庫 → novel-bible；大綱章綱 → novel-outline；寫章節與改稿 → novel-write；一致性審查 → novel-review；去 AI 味與用語校正 → novel-deslop。
- 寫正文需要作者明確說要寫哪章，或說「繼續寫」。單章預設 1 章，一次最多 3 章。
- 只說「繼續」「按這個來」時，不擴大範圍：規劃階段就只做規劃，不自動開寫正文。
- 給作者的匯報用白話：寫了什麼、有什麼要作者決定、下一步。不講檔名欄位等技術細節，除非作者問。
- 作者說「以後都……」「記住……」這類長期偏好時，記到 `設定/作者偏好.md`；一次性要求只執行不記錄。
