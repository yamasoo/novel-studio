# 開書訪談

目標：用最少的問題，拿到建專案需要的資訊。作者可以隨時說「跳過」「你決定」「隨便給我幾個」，這時由你提出 2～3 個選項讓作者挑，或直接採用最合理的預設並標明是預設。

一次只問一輪，每輪最多 4 題。有提問工具（多選題介面）就用它，選項附「推薦」標記。

## 第一輪：故事是什麼（必問）

1. **題材與一句話構想**：想寫什麼？（一句話、一段簡介、或幾個關鍵字都可以）
2. **目標讀者與平台**：給誰看？在哪裡發表？（例：男頻／女頻、起點／晉江／自己的部落格、只是自己寫爽）
3. **篇幅**：預計多長？（短篇 3 萬字內／中篇 10～30 萬／長篇 50 萬以上／還不確定）
4. **書名**：有暫定書名嗎？（沒有就先用構想裡的關鍵字當資料夾名）

拿到第一輪就能判斷題材與規模。如果作者給的構想太模糊，壓不出「主角是誰、想要什麼、被什麼擋住」，在第二輪補問，不要自行腦補成完整設定。

## 第二輪：怎麼寫（必問）

1. **視角**：第一人稱、第三人稱跟著主角、還是多視角／全知？
2. **每章字數**：（網文常見 2000～4000 字；不確定就用 2500～3500）
3. **文風方向**：喜歡哪種感覺？可以舉作品、作者，或描述（例：輕快吐槽、冷硬簡潔、細膩抒情、古風雅致）。
4. **寫作樣本**：有沒有自己寫過的段落，或特別喜歡的文字可以貼上來？（最有用的資料；沒有也可以）

## 第三輪：規矩與禁忌（選問）

只在作者有興趣時問，或從前兩輪回答中自然帶出：

1. **一定要有的**：例如感情線、爽點類型、某種結局。
2. **一定不要的**：例如虐主、後宮、某類情節、某些用詞。
3. **讀者契約**：你想向讀者保證什麼？（例：主角不聖母、一對一、不爛尾）
4. **工作習慣**：例如每章寫完要先給你看、要不要自動做一致性檢查、匯報要多詳細。

## 處理寫作樣本

作者貼了樣本時：

1. 分析它的特徵：句子長短、段落密度、對白比例、情緒是直寫還是用動作呈現、比喻多寡、敘述距離、標點習慣、有沒有口頭禪或固定節奏。
2. 用條列寫進 `設定/文風.md` 的對應欄位，每條要具體到能照著寫（「短句多」不夠，要寫「緊張場面多用 10 字以內短句，一般敘述句長交錯」）。
3. 把樣本本身放進 `設定/文風.md` 的「範例段落」，附一句你判斷它好在哪。
4. 給作者看你歸納的文風重點，請他修正。

作者沒有樣本時，依照他描述的方向寫出 2～3 條具體文風規則，再寫一段 150 字左右的示範段落，請他判斷「是不是這個感覺」。作者說不像，就問哪裡不像，再改。

## 訪談結束後

把結果整理成三份檔案的初稿：
- `CLAUDE.md`：依 references/claude-md-template.md
- `設定/故事核心.md`：填入已知的部分，未知的保留範本註解
- `設定/文風.md`：依上面的樣本處理結果

然後用一段白話告訴作者：專案建在哪、已經填了什麼、哪些還空著，以及建議的下一步（通常是用 novel-outline 把故事核心補完，或用 novel-bible 建主角設定）。
