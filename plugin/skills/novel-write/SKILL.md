# novel-write：寫章節

你負責把章綱寫成正文，並在寫完後把「已發生的事實」回寫到追蹤資料。長篇不會前後矛盾，靠的是每章都把這一步做完。

## 判斷任務與範圍

| 作者說 | 任務 | 範圍 |
|---|---|---|
| 「寫第N章」 | 寫指定章 | 只寫這一章 |
| 「繼續寫」「寫下一章」「接著寫」 | 續寫 | 下一章；作者說「寫三章」才寫三章 |
| 「日更」 | 續寫 | 預設 2 章 |
| 「改第N章」「這段改一下」「重寫第N章」 | 改稿 | 見文末「改稿流程」 |
| 只說「寫」但不清楚寫什麼 | 不動筆 | 先看專案進度，給 2～3 個選項讓作者選 |

**一次最多寫 3 章。** 多章時一章一章完整做完（包含回寫追蹤），再寫下一章。超過 3 章的要求，寫完 3 章後在匯報說明，請作者確認再繼續。

## 第一步：前置檢查（任一項不過就停）

1. 有 `CLAUDE.md`？沒有 → 請作者先用 novel-setup。
2. 這章有章綱 `大綱/章綱/第NNN章.md`？
   - 沒有 → 停下，問作者要不要先用 novel-outline 排章綱。（作者說「你直接寫」時，可以先補一份最小章綱給作者看：四問、情節點、章末鉤子，作者點頭再寫。）
   - 章綱 `狀態` 是 `草稿` → 問作者「第N章章綱還是草稿，要照這個寫嗎？」
3. 追蹤有更新到上一章？看 `追蹤/狀態卡.md` 的 `更新至`。落後 → 先補完上一章的回寫，再寫這章。不要在落後的狀態上寫新章。（例外：候選稿模式一次寫多章時，後面幾章以前一章的候選稿承接，見「候選稿模式」。）
4. 第一章時，追蹤檔可能還是空白範本，這是正常的。

## 第二步：寫前必讀

依序讀完，不要跳過：

1. `設定/文風.md`、`設定/作者偏好.md`
2. 本章章綱全文
3. `追蹤/狀態卡.md` 全文
4. 章綱「出場角色」裡每個角色的 `設定/角色/` 與 `追蹤/角色狀態/`
5. `追蹤/伏筆.md` 中章綱提到的伏筆，以及狀態卡「活躍伏筆」列的伏筆
6. `追蹤/時間線.md` 中與本章角色或事件相關的行，特別注意「讀者目前知道」
7. 上一章正文的最後 800 字左右（承接語氣與場景）
8. 章綱提到的勢力、世界觀、名詞（查 `設定/` 與名詞表）
9. 本對話中第一次寫正文時：[references/writing-craft.md](references/writing-craft.md)。需要參考寫法時另讀 [references/examples.md](references/examples.md) 對應的段落。
10. 專案有 `範例/` 資料夾且有內容時，讀一兩段作者的正例。

## 第三步：寫前計畫（在心裡做，不用給作者看）

寫下這一輪的約束，寫正文時對照：
- **必須發生**：章綱的每個情節點
- **禁止發生**：章綱的禁止事項、時間線中還不能揭露的事、還不能用的底牌
- **字數**：章綱 `字數目標`，沒有就用 CLAUDE.md 的每章字數
- **停在哪裡**：章末鉤子
- **一句話意圖**：例「先憋後爆——當眾被退婚→反問婚書印章→眾人變色→沈既白第一次失態」
- **人物狀態承接**：每個主要角色上一場結束時的目標、情緒、關係溫度、身體狀態，這一場什麼會讓他改變
- **定稿對帳**：把章綱每個情節點和已定稿事實（狀態卡、角色狀態、時間線的「讀者目前知道」、上一章結尾）逐條比對。發現衝突（角色不在場、物品不在手上、讀者還不該知道、時間對不上）時，採用與定稿一致的寫法，並在匯報列出衝突與處理方式；衝突大到必須改變章綱結果時，屬於「先問作者」

文風優先順序：作者這次的要求 ＞ 文風.md ＞ 作者偏好.md ＞ writing-craft.md。

## 第四步：寫正文

- 直接寫進 `正文/第NNN章_章名.md`，不要先貼在對話裡。檔案第一行是 `# 第N章 章名`。
- 台灣繁體中文；標點用「」『』……——；全形標點。
- 照章綱的情節點順序展開成場景，不要把情節點句子換個說法串起來。
- 遇到章綱沒寫的空白，照 CLAUDE.md 的「新增物三級」處理：
  - **直接寫**：路人、小道具、場景細節
  - **寫了要報**：具名配角、新規則、新伏筆、新關係或承諾。照寫，記下來，第六步申報
  - **先問作者**：主線事件、大反轉、金手指規則、揭露真相、改變章綱結果。**不寫**，記下來，第六步問作者

## 第五步：自查

1. **情節點全落**：章綱每個情節點至少出現一次。漏了就補寫，不能拿字數當理由。逐項確認時，替每個情節點找出正文裡對應的一句原文；找不到原文就代表沒寫到。
2. **禁止事項**：沒有違反。
3. **資訊邊界**：沒有說出讀者還不該知道的事，沒有「殊不知」「他不知道的是」這類偷跑。
4. **四問**：本章結束後局面確實變了；結尾有往下看的理由。
5. **主角的功勞**：
   - 主角是靠自己的選擇或能力拿到本章結果的嗎？
   - 收益有沒有被配角、長輩、機構、巧合無代價地拿走？
   - 有沒有提前動用後面才該出現的底牌？
   - 舊的期待有沒有給一點兌現，同時留下新的期待？
   任一題不過，就在章綱允許的範圍內修；修不了就在匯報裡告訴作者。
6. **三類 AI 腔**：照 writing-craft.md 第八節逐段重讀（替讀者點題、敘述者跳出來解釋、章尾感悟預告），以及工程詞外洩。
7. **工具檢查**：若已安裝 novel-deslop，執行它的檢查腳本（見 novel-deslop 的 SKILL.md「自動檢查」），處理必須修的項目。沒有就跳過，不要因此停住。
8. **字數**：和目標差超過 20% 時，不要自己注水或硬砍。依 [references/report-template.md](references/report-template.md)「字數差太多」問作者。

## 第六步：申報新增物

列出第四步記下的新增物：
- 有「先問作者」項 → 依 report-template.md「需要作者決定」問作者，**暫停**，不做第七步，也不寫下一章。
- 只有「寫了要報」項 → 照常進第七步，登記它們。
- 都沒有 → 進第七步。

## 第七步：回寫追蹤

完整依 [references/tracking-update.md](references/tracking-update.md) 執行：章節摘要、狀態卡、角色狀態、伏筆、時間線、設定登記、章綱狀態、git 提交。

這一步不能省。下一章的品質完全依賴這一步的準確度。

## 第八步：匯報

依 report-template.md 的「寫完一章」或「一次寫多章」模板。

一次寫了 3 章，或這章有較多新增物時，在匯報最後建議：「要不要跑一次 novel-review 做一致性檢查？」

## 候選稿模式（給審稿介面用）

作者或指令說「候選稿模式」「寫成候選稿」，或指令來自小說工作台時：

1. 第一～六步照常，但正文寫進 `候選/第NNN章_章名.md`，不是 `正文/`。`候選/` 不存在就建立。
2. 做完第五步自查與第六步申報後**停止**：不做第七步回寫追蹤、不改章綱狀態、不 git 提交。
3. 依 report-template.md 匯報，最後一行改成：「候選稿在 候選/ 裡，請審閱後採用或退回。」
4. 一次寫多章時：每章都只寫成候選稿。寫第二章時，以第一章**候選稿**的內容承接（因為追蹤還沒更新），並在匯報提醒作者要依序採用。

作者採用後（候選稿已被移到 `正文/`），會收到「從第七步開始回寫」的指令：直接讀正文，執行第七步與第八步。

作者退回並附意見時：照意見改寫 `候選/` 裡的那份稿子，仍然不回寫追蹤。

## 改稿流程

作者要修改已寫章節時：

1. **確認範圍**：改哪裡、改成什麼方向。不清楚就問一句。「這段改一下」只改那段；「重寫第N章」才整章重寫。
2. 讀該章正文、章綱、章節摘要，以及第二步的相關資料。
3. **判斷改動層級**：
   - 只是文字、節奏、對白的修飾 → 直接改，不涉及追蹤。
   - 改變了事實（誰知道什麼、誰受傷、物品去向、關係、伏筆）→ 改完後依 tracking-update.md 的「改稿時的回寫」處理。
   - 改變了章綱的結果 → 先問作者是否同意，並說明會影響後面哪些章節。
4. 改完在匯報中說明：改了什麼、影響了哪些追蹤資料、後續哪些章節可能需要對齊。

## 注意

- 每章完整做完再寫下一章，不要先寫三章再一起回寫。
- 作者在寫作過程中說的長期偏好（「以後都……」），記進 `設定/作者偏好.md`。一次性要求只執行。
- 不要為了湊字數加章綱以外的劇情；不要為了精彩提前透支後面的伏筆。
